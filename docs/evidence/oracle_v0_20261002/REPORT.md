## 问题和可复用修复

1. Franka 的默认收臂姿态装上 XHand 后自碰撞。初态现在按完整装配几何检查并选择；状态设置仅发生在 t=0 前。
2. 入口 IK 原本使用裸 Franka 模型，而路径检查包含 XHand。入口搜索统一使用完整碰撞几何，自由手候选偏移由物体尺寸生成。已抓持入口保留实际手物关系。
3. 均匀压缩路径到原时限会超速、超加速度。改为沿同一几何路径分配速度，再检查固定预算、碰撞及实际执行。该例规划指令速度比 0.952、加速度比 0.896；没有改变时限或验收阈值。
4. 位置控制未接入规划速度，产生约 0.2 秒的跟踪滞后。直接传规划速度作前馈后，交接误差降至 0.008457 rad。前馈不从跨段旧位置目标差分计算，以免把静态误差变成启动脉冲。
5. 首个 Anchor 的独立逐帧 IK 有最大 0.966 rad 的相邻帧跳变。已改连续 IK，并在局部重定向中加入物理步长的速度/加速度约束；本地约束检查通过，**其物理交互效果尚待 Hopper 验证**。

这些改动不分支判断序列名、任务名或固定帧号。帧号只存在于 oracle 数据中。当前仅证明桥段修复有效，没有声称跨任务物理成功。
