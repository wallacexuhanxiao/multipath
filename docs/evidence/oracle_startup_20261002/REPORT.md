# Mounted Anchor 接管诊断 — 本轮报告

## 结论

M1/r10 bridge 保持冻结。当前仍没有通过局部物理验收的 Anchor，完整 4.8 秒 rollout 未完成。

本轮排除了“恢复时旧驱动目标是主要原因”的猜测，并找到两个具体问题：

1. 局部拟合只约束机械臂，手指指令没有限速；arm 与 hand 同时执行时发生动态耦合超限。
2. MPC 严格比较浮点关节边界，误将零附近的舍入误差判为越界，导致基准候选进不了物理预测。

## 实测：同一个真实入口，前 10 个物理步

入口来自 r10 的真实 source frame 29。每个对照从同一 snapshot 开始，无额外 settle。
诊断为观察瞬态继续记录了越限后的 10 步；这些轨迹明确不作为成功 artifact。

| 对照 | 第一步最大加速度/限值 | 前 10 步最大加速度/限值 |
|---|---:|---:|
| 原恢复目标＋原指令 | 1.699 | 15.255 |
| 恢复目标对齐实测 q/dq＋原指令 | 1.699 | 16.526 |
| 对齐目标，改为左端点发指令 | 0.734 | 12.977 |
| 原 arm 轨迹，hand 保持入口姿态 | 0.953 | **0.956** |
| 原 hand 指令，arm 保持入口速度 | 0.753 | **0.753** |
| 原 arm 轨迹，hand 限速且首步延续实测速度 | **0.953** | **1.319，仍失败** |

前五项来自 r17（642905）；最后一项来自 r18（642927）。第一轮 r16（642899）验证恢复目标比较。
记录包含实际 q/dq、PhysX 内部 position/velocity target、position error、关节测量力矩、显式 effort command 和 PD 估算值；PD 估算不能当作实测驱动力矩。

原手指第一步隐含目标速度约 28–50 rad/s，对应 URDF 限速约 8.6–14.4 rad/s。
原 arm 单独执行通过，联合执行失败；只对齐驱动目标无法解决。
限速修复让第一步通过，但第 2–4 步仍超限，说明速度连续性和加速过程也必须处理。

## 已实现的修复与验证边界

- snapshot 恢复后默认将驱动位置/速度目标对齐实测 q/dq；不推进时间。诊断保留旧行为作对照。
- 手指局部拟合读取 URDF 关节位置和速度限制，首个控制区间延续 measured dq；控制步数和源时间不变。
- 新版本进一步使用已有 pre-padding 时长建立手指加速预算：速度限值 / context 时长。这是合成算法的 slew budget，**不是宣称获得了手指硬件加速度额定值**。r19 实测前 10 步最大加速度比降至 1.095587，但仍超过原 1.05 验收线，失败。
- MPC 使用可解释的共享预检查，记录速度、加速度和具体关节越界项。边界只增加 float32 表示精度级容差，实际 actuator gate 不变。
- 原基准候选含 -2.5e-19 rad（下限 0），以及 -0.175 与 float32 下限 -0.174999997 的表示差异。修复后，同一原始 48 步基准候选通过 nominal precheck：arm 速度比 0.98、加速度比 0.95。这**不代表它通过物理执行**。

仅保留两项针对实际失败的离线回归：浮点误差不能拒绝基准候选、手指拟合保持源步数和入口速度；两项通过。未新增大测试集。
